# Style library and mechanism analysis

## Organize what was observed

Cluster by editing grammar rather than creator prestige or color alone. Assign
one primary family and optional tags per inspected clip. Name hybrid families
when their repeated grammar warrants it; do not force every source into a
predefined template. These are useful starting labels, not performance claims:

| Family | Observable signature | Useful task fit |
| --- | --- | --- |
| `kinetic-type` | Words change scale, position or emphasis with the message; type carries the sequence. | Compact messages, slogans, spoken hooks. |
| `editorial-collage` | Cutout footage/photos, documentary fragments, texture or diagrams combine in layered frames. | Narrative contrast, cultural context, visual metaphors. |
| `diagram-explainer` | Objects, charts, maps or diagrams change with the explanation. | Processes, cause/effect and measured comparisons. |
| `product-demo` | Actual product/UI state, interaction and visible outcome lead the sequence. | Showing a task, feature or before/after benefit. |
| `presenter-overlays` | A speaker anchors the story; captions, inserts and graphics reinforce specific moments. | Expertise, demonstrations and personal delivery. |
| `cinematic-story` | Shot selection, camera/framing, sound and narrative progression carry the meaning. | Emotion, tangible experience or scene-based storytelling. |

A title or thumbnail alone supports only a provisional classification. Mark
unviewed clips `visual-unverified`. A style label says what the clip does; it
does not establish why its audience responded.

## Required research artifacts

For discovery work, produce `research.json`, `ranked.json` and `styles.md`, or
the user's exact equivalents. Preserve source snapshots and frame evidence in
the task project. Do not put a changing public leaderboard in this skill.

The research record retains scope, UTC observation time, queries, original URLs,
creator IDs, publication dates, durations, metric definitions, available counts,
access/verification states, peer IDs, exclusions and limitations. Include actual
search coverage so a shortlist is not presented as a census of the platform.
The ranking output comes from the bundled helper; preserve its comparable
cohorts, peer exclusions and formulas in the report. Keep any user-requested
alternative calculations in a separate named analysis.

Make the human-readable report easy to use:

1. State scope and the ranking basis. Show strong candidates within each
   comparable cohort, with links, counts, ages, baseline size/ratio where
   available, and uncertainty. Keep reach, channel-relative standing and fit
   distinct. Show why notable candidates were excluded or left unranked.
2. Group inspected references into style cards. Each card names the family,
   representative URLs, observed signature, useful content goals, production
   requirements and confidence. Distinguish provisional from inspected clips.
3. Order the recommended styles for the actual task. Lead with supported
   performance evidence and relevant content fit; explain each placement. If
   outcome evidence cannot order two families, say the order reflects task fit.
   A family with only a famous historical example cannot become a current winner.
4. For every recommended family, explain specific mechanisms using the structure
   below. Select representative clips for detailed timestamped analysis before
   turning a family into a production recipe.

## Explain what might make it work

For each important mechanism, record:

| Field | Required distinction |
| --- | --- |
| Observation | What changes on screen or in the sound, with source ID, time range and actual evidence frames/playback. |
| Viewer function | The concrete operation it may help: notice a contrast, read a phrase, track an object, understand a step or anticipate a payoff. |
| Performance evidence | The observed metric and comparable rank; retention or conversions only when authorized data actually supports them. |
| Hypothesis | Why the observed device might support the viewer function; identify this as an inference. |
| Confounders | Topic, title/thumbnail, creator distribution, promotion, celebrity, timing or another credible explanation. |
| Reuse/test | A transferable editing rule and a small comparison that could test the hypothesis. |

Example of a valid explanation: a word enlarges when the narration names the
decision; adjacent frames establish the synchronization; the hypothesis is
that emphasis helps viewers locate the decisive term. An A/B comparison could
keep narration and message fixed and vary that emphasis, measuring the owner's
available comprehension or retention outcome. This example does not establish
a universal retention gain or prescribe an effect for every video.

Check the opening promise, information density/readability, rhythm and holds,
semantic alignment of graphics/speech, visible proof or payoff, and ending/loop
when relevant. Record an absent feature as absent, not a requirement to add it.
A rapid-cut piece can fail when the message needs reading time; a static hold
can be the observed grammar. Do not equate more motion, more effects or more
cuts with effectiveness.

Keep validated style rules in the selected `style.json`, with supporting
observation IDs and separate original additions. A reusable family needs
multiple examples before claiming shared conventions; one example can support
a useful candidate recipe with explicit limits. Inaccessible media can supply
public reach evidence while leaving its visual grammar unverified.
